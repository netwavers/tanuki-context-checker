# 生成AI文章チェッカー 評価基準・テストベンチマーク仕様書 (EVALUATION_CRITERIA.md)

**文書バージョン**: 1.0.0  
**適用範囲**: [Stage 1] 評価用コーパス作成・テスト基準策定 (TAN-90)  
**正本仕様書**: `docs/ARCHITECTURE_SPEC.md` 及び `生成AI文章チェッカー 要求定義書（仕様）.md`

---

## 1. 目的と評価基本方針

本仕様書は、生成AI文章チェッカー（Tanuki Context Checker）の精度検証、各解析層（表層・語彙・構造・フロー）のスコア閾値、およびドメイン補正モデルの評価基準を定義する。

システムが測定するのは「文章の美しさや文法的な正しさ」ではなく、**「人間らしい思考のゆらぎ（自己訂正、脱線、非均一な力点、暗黙の参照関係）の欠如度 $\mathcal{D}_{\text{homogeneity}}$」** である。

---

## 2. 評価スコア帯と判定ラベル定義

全層の加重統合およびドメイン補正適用後の最終 AI 確率スコア $S(T) \in [0.0, 100.0]$ に基づき、以下の 3 区分に分類する。

| スコア帯 | 判定ラベル (`ClassificationLabel`) | 意味と文章の定性特徴 | 運用上の推奨アクション |
| :--- | :--- | :--- | :--- |
| **0.0 ～ 30.0** | `HUMAN_FLUCTUATION_STRONG` | **人間らしいゆらぎが強い**<br>思考の脱線、自己訂正、一人称経験談、不一様な段落・文長、暗黙の文脈共有が顕著。 | 自動承認（Human Verified） |
| **30.1 ～ 69.9** | `MIXED_NEEDS_REVIEW` | **混在・要確認**<br>人間の入念な推敲文書、AI生成文の人間による大幅編集、または定型度の高い人間文章。 | 人間による目視確認推奨 |
| **70.0 ～ 100.0** | `AI_HOMOGENEOUS_HIGH` | **AI生成の可能性が高い（均質な構成）**<br>AST深さ・段落長の分散が極めて低く、AI頻出定型句・ヘッジ表現・消し忘れMarkdownが高密度。 | フラグ立て / フラグ付与 |

## 3. 解析層別評価メトリクスとシグナル判定基準

### 3.1 表層記号解析層 (`SurfaceMetrics`)
- **Markdown異常スコア**: AIが出力時に残す消し忘れプロンプト記号（例: ```markdown 残留、過剰な `bold` 強調、連続する `---` 区切り）。
- **記号均一性**: 感嘆符・疑問符・emダッシュ（―）が規則的周期で出現する度合い。

### 3.2 語彙・表現密度解析層 (`LexicalMetrics`)
- **AI頻出定型句密度**: 「〜について徹底解説」「以下のポイントに留意」「まとめとして」等のAI定型テンプレート句の検出密度。
- **N-gramエントロピー**: 語彙の多様性と出現確率の不確かさ（AI文は中庸〜高い語彙多様性を示すが局所N-gram重複が低分散）。
- **ヘッジ表現率**: 「一般的には〜とされる」「一説には〜と考えられる」などの責任回避・抽象的ボイラープレートの割合。

### 3.3 構造統計解析層 (`StructuralMetrics`)
- **AST深さ分散 $\text{Var}(\text{Depth})$**: 各節・文の木構造深さのバラツキ（人間は浅い文と複雑な複文が混在し分散大）。
- **文長・段落長の変動係数 ($\text{CV} = \sigma / \mu$)**:
  - $\text{CV}_{\text{paragraph}} < 0.15$ かつ $\text{CV}_{\text{sentence}} < 0.20$ の場合、AI特有の均質構造シグナルとして高加点。
- **ノード型エントロピー**: 構文要素の構成比率のエントロピー。

### 3.4 フロー・ゆらぎ解析層 (`FlowMetrics`)
- **話題ジャンプ密度 (Topic Jump Density)**: 談話ベクトル間の余弦類似度急減（$\Delta \text{Embed} > \theta$）による「脱線・脱離」の正の人間シグナル。
- **自己訂正・軌道修正数 (Self-Correction Count)**: 「いや、正確には」「というよりは」などの思考上書き表現のカウント。
- **一人称・具体経験表現密度**: 一人称代名詞（「私」「僕」「当方」）および時系列エピソード表現の存在。
- **未解決暗黙参照数 (Unresolved References)**: 前提知識を省略した主語・指示代名詞の適度な存在（正の人間シグナル）。

## 4. ドメイン補正モデル (Domain Baseline Specification)

技術仕様書・学術論文・公式レポートなど、人間が意図的に構造を整えた文章での偽陽性（誤検出）を防止するため、ドメイン毎に補正パラメータを適用する。

$$
S(T) = \frac{100}{1 + \exp\left( - \left( \mathbf{w}^T \mathbf{x} - b_D - k_D \cdot D_M(\mathbf{x}) \right) \right)}
$$

### ドメイン別基準パラメータテーブル

| ドメイン名 (`DomainType`) | バイアス項 $b_D$ | 補正強度 $k_D$ | 構造スコア重み減衰率 | ドメイン特性と補正理由 |
| :--- | :---: | :---: | :---: | :--- |
| `technical_doc` | $-0.35$ | $0.85$ | $0.40$ (60%減) | 仕様書・設計書は構造が均一化しやすいため、構造均一性による加点を強力に抑制。 |
| `academic_paper` | $-0.40$ | $0.90$ | $0.30$ (70%減) | 学術論文は客観的受動態・定型構成が標準であるため、一人称欠如・構造均一のペナルティを相殺。 |
| `report` | $-0.15$ | $0.60$ | $0.65$ (35%減) | 業務報告・調査レポート。適度な構造化を許容。 |
| `blog` | $0.00$ | $0.40$ | $0.80$ (20%減) | 技術ブログ・解説記事。一定の口語表現とゆらぎが期待される。 |
| `essay` | $+0.10$ | $0.20$ | $1.00$ (減衰なし)| 散文・エッセイ。ゆらぎの欠如は強いAIシグナルとして評価。 |

## 5. ベンチマーク評価指標と合格受け入れ基準 (Acceptance Criteria)

評価コーパスを用いたシステム全体系の検証（Stage 3 / Stage 4）における合格指標を以下の通り定義する。

1. **全体分離度 (Overall Separability)**:
   - 人間執筆サンプル群と AI 生成サンプル群における ROC-AUC $\ge 0.92$。
2. **技術文書偽陽性率 (False Positive Rate for Technical Docs)**:
   - ドメイン補正適用後の `technical_doc` における人間文章の誤判定率 $\text{FPR}_{\text{tech}} \le 0.05$ (5%以下)。
3. **AIプロンプト模倣検出率 (Detection Rate for Prompt-Engineered AI)**:
   - 「ゆらぎを指示されたAI文章」に対する検出再現率 $\text{Recall}_{\text{prompt\_engineered}} \ge 0.85$。
4. **短文境界挙動 (Short Text Boundary Handling)**:
   - 100文字未満のテキスト入力に対しては判定をスキップし、`ConfidenceFlag.INSUFFICIENT_LENGTH` を正確に返却すること。

## 6. コーパス構造化ファイルの構成と検証仕様

コーパスデータセットは `tests/corpus/evaluation_corpus.json` に格納し、`tests/corpus/dataset_schema.py` の Pydantic スキーマに完全準拠する。  
`tests/corpus/validate_corpus.py` スクリプトにより自動検証を実行し、型・文字数・ドメイン・スコア帯の不整合をゼロとする。
